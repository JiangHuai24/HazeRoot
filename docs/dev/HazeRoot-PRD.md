# HazeRoot 产品需求文档（PRD）

> 版本：v1.0 · 角色：产品经理（PM）· 状态：待评审
> 依据：工程化重构方案、交互与实现改造规格、UI 设计建议书、技术根因诊断
> 目的：把「痛点」转成「可验收的需求条目」，作为后续架构拆解与代码改造的唯一验收基准。

---

## 0. 产品定位与目标

**一句话定位**：HazeRoot 是一个「通用 root 脚本执行器」，让 root 用户把「手动敲一堆回答」变成「点一下跑完」，并辅以 MT 管理器式的文件管理能力。

**核心目标用户**：进阶 root 用户 / 脚本作者 / 从 MT 管理器迁移来的效率工具用户。

**本次迭代的北极星目标**（一句话）：**让 HazeRoot 从「功能堆叠、勉强能用」变成「逻辑清晰、交互对齐 MT、终端门面有产品质感」的工程化产品。**

## 2. 用户故事 + 验收标准（Given/When/Then）

### FR-1 终端渲染根治（P0）

**用户故事**：
> 作为脚本作者，我想要终端**完整、实时、不乱码**地显示脚本输出（含中文/ANSI 彩色/长输出），以便我能判断脚本执行状态并正确应答。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC1.1 | Given 一个 UTF-8 中文脚本，When 执行，Then 终端逐行完整显示中文，**不出现 `�`、`?`、乱码、丢行** | 功能 |
| AC1.2 | Given 一个 GBK/UTF-8 混合输出脚本，When 执行，Then 两种编码在同一屏各自正确解码，无错位 | 功能 |
| AC1.3 | Given 一个带 ANSI 颜色/清屏/光标的脚本，When 执行，Then 颜色正确渲染、清屏/光标行为正确 | 功能 |
| AC1.4 | Given 超长输出（>20 万字符），When 执行，Then 不 OOM、不 ANR，最旧内容按**行边界**丢弃并提示「已截断」 | 性能 |
| AC1.5 | Given 1000 行海量输出，When 连续追加，Then 主线程单帧耗时 ≤ 16ms，无明显掉帧 | 性能 |
| AC1.6 | Given 用户在终端**上翻**查看历史，When 新输出到达，Then **不强制拽回底部**；用户滚回底部后恢复自动吸底 | 交互 |
| AC1.7 | Given 长跑脚本无输出，When 静默超时，Then 显示「已 N 秒无输出」提示（保留现有看门狗行为） | 功能 |

**关键实现约束**（引自交互规格 A 节）：
- 字节流式跨块 UTF-8 解码器（`mUtf8ToFollow/mUtf8Index` 跨 chunk 保持状态，禁止按 chunk `new String` 重解码）；
- 行级脏标记 + 可见行全量重绘（禁止逐字符脏渲染）；
- 显式「吸底/上翻」状态机；
- 环形缓冲按**行边界**裁剪。

### FR-2 文件页长文件名显示（P1）

**用户故事**：
> 作为从 MT 迁移的用户，我想要文件名的**关键部分（尤其是扩展名）始终可见**，并能方便地查看完整路径，以便快速识别文件类型。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC2.1 | Given 一个超长文件名（如 `Fuzz_Cheat_v4.1_backup_2026.sh`），When 列表展示，Then 主行用 `ellipsize=middle` 保留「首段 + … + 尾段.ext」，**扩展名永不丢失** | 功能 |
| AC2.2 | Given 文件名被截断，When 用户长按该条目，Then 弹出完整文件名 + 完整路径（可复制） | 交互 |
| AC2.3 | Given 文件列表，When 展示，Then 每项有「类型图标（颜色+图标双编码）+ 名称 + 大小·时间」清晰信息层级 | UI |
| AC2.4 | Given 深路径，When 显示路径栏，Then 用面包屑可点跳转，长路径折叠为「…/末级」，且可点当前项弹文本框手动输入 | 交互 |

### FR-3 手势交互状态机重构（P0）

**用户故事**：
> 作为用户，我想要文件页的手势**可预测、不冲突、不闪退**（点按=打开、长按=多选、左滑=单条操作、多选下点按=切换选中），以便像 MT 一样靠肌肉记忆操作。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC3.1 | Given 浏览态，When 点按条目，Then 打开/执行该条目 | 功能 |
| AC3.2 | Given 浏览态，When 长按条目，Then 进入多选并选中该项（含震动反馈） | 功能 |
| AC3.3 | Given 多选态，When 点按条目，Then 切换该条选中态（**不打开**） | 功能 |
| AC3.4 | Given 浏览态，When 左滑条目，Then 弹出该条单条操作菜单（**不进入多选**） | 功能 |
| AC3.5 | Given 多选态，When 左滑，Then **忽略**（禁止多选下左滑做单条操作） | 功能 |
| AC3.6 | Given 快速滚动 + 点击，Then **不出现虚影、不闪退**（历史 bug 不复现） | 稳定性 |
| AC3.7 | Given 多选态，When 选中数归零，Then 自动退出多选、恢复顶部工具栏 | 交互 |

**关键实现约束**（引自交互规格 C 节）：
- 单一 `GestureController` + 四态状态机（NORMAL/MULTI/ACTION_MENU/DRAG_SCROLL）；
- 事件用坐标快照，**不捕获 RecyclerView row/view 引用**（根治虚影/闪退）；
- `GestureController` 随 Adapter 生命周期只建一次，不每次 bind 重建。

### FR-4 队列添加与去重反馈（P1）

**用户故事**：
> 作为用户，我想要从任意入口（文件页/链接/手动）添加脚本到队列时，**有统一的去重和明确反馈**，以便知道「加没加上、是不是重复了」。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC4.1 | Given 三个入口（文件页选脚本/链接导入/手动输入），When 添加脚本，Then 走**同一 `enqueue()` 入口**，成功/重复/失败的反馈一致 | 功能 |
| AC4.2 | Given 队列中已有脚本 A，When 再次添加同一路径，Then 提示「已在队列中」而非重复入队 | 功能 |
| AC4.3 | Given 入队成功，When 反馈，Then 队列 Tab 徽标 +1（或 Snackbar） | 交互 |
| AC4.4 | Given 手动输入不存在的路径，When 提交，Then 报错并允许「仍要添加」 | 功能 |

---

### FR-5 执行中页面联动（P1）

**用户故事**：
> 作为用户，我想要执行脚本时**能自动看到进度**，且各页面能感知「正在执行」状态，以便不迷失在「点了执行却没反应」的困惑里。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC5.1 | Given 文件页点「执行」，When 开始执行，Then **自动切到队列/终端页**显示输出 | 联动 |
| AC5.2 | Given 文件页点「加入队列」，When 入队，Then **停留在文件页**（批量添加不打断） | 联动 |
| AC5.3 | Given 执行中，When 用户在任意页面，Then 底部导航/顶部显示**全局执行状态徽标** | 联动 |
| AC5.4 | Given 执行完成，When 收尾，Then 默认停留队列页 + Snackbar 报告结果（可选「完成后回来源页」） | 联动 |
| AC5.5 | Given 跨页通信，When 触发，Then 走**单一事件总线**（AppEventBus），无静态可变状态传参残留 | 架构 |

---

### FR-6 MT 交互范式对齐（P1）

**用户故事**：
> 作为从 MT 管理器迁移的用户，我想要核心文件操作的手势/视觉与 MT 一致，以便零学习成本上手。

**必须对齐 6 项**（验收基准）：
1. 长按 = 多选；2. 顶部 CAB 批量操作条；3. 双窗当前窗高亮；4. 面包屑路径；5. 左滑 = 单条操作；6. 长文件名截断。

**可差异化 3 项**（HazeRoot 优势）：终端面板质感、脚本队列联动、自动应答交互。

| # | AC | 类型 |
|---|---|---|
| AC6.1 | Given 6 项对齐项，When 逐一操作，Then 行为与 MT 一致（见交互规格 E 节对照表） | 功能 |

---

### FR-7 UI 视觉换肤（P1）

**用户故事**：
> 作为作者，我想要一套「冷色主调 + 品牌冷青蓝 + 琥珀暖点缀 + 中性石墨外壳」的克制 UI，**没有 AI 味**，且终端门面有产品质感，以便形成 HazeRoot 的品牌印象。

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC7.1 | Given 主色，When 检查，Then 品牌主色为冷青蓝（~#3B6FE0），**废弃紫色 #635BFF**（AI 味主要来源） | UI |
| AC7.2 | Given 外壳，When 检查，Then 中性石墨灰阶（浅 #F5F6F8 / 深 #0F1115），**无大面积彩色底** | UI |
| AC7.3 | Given 状态表达，When 检查，Then 运行中=琥珀 #E8A33D、成功=绿、失败=红、闲置=灰，颜色只服务「状态」与「品牌」 | UI |
| AC7.4 | Given 终端面板，When 检查，Then 独立深色底 + 等宽字 + 光标闪烁，自成「设备面板」 | UI |
| AC7.5 | Given 卡片，When 检查，Then 1dp 描边区分，不用重阴影/彩色底 | UI |
| AC7.6 | Given 底部导航，When 检查，Then 单色极简（选中亮/未选中灰），**去掉彩色胶囊底** | UI |
| AC7.7 | Given 动效，When 检查，Then 切页 crossfade 200ms、运行中呼吸、滚动吸底，无转场炫技 | 动效 |

> 注：FR-7 的具体色值/间距在《UI 设计建议书》与后续 UI 规格中细化，此处仅定方向性 AC。作者已表达对「青蓝替代紫」方向待最终确认——**在作者确认前，FR-7 不进入编码**。

### FR-9 业务框架 / 模块划分 / 数据流（P0，重构前置）

**验收标准**：

| # | AC | 类型 |
|---|---|---|
| AC9.1 | Given 重构后，When 检查，Then `Engine/FilesFragment/QueueFragment` 各自拆分，**单类 ≤300 行、单方法 ≤40 行**（Checkstyle 门禁） | 架构 |

## 3. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-1 | 性能：终端海量输出单帧 ≤16ms；文件列表滚动流畅 |
| NFR-2 | 稳定性：手势操作零闪退、零虚影（回归测试覆盖） |
| NFR-3 | 兼容：minSdk 26 / targetSdk 34，root 方案 Magisk/KernelSU/APatch 均可用 |
| NFR-4 | 可测试性：解码器/ANSI/状态机/入队契约均有单元测试，核心路径覆盖率 ≥60% |
| NFR-5 | 可维护性：单类≤300 行、单方法≤40 行、单向依赖（门禁强制） |
| NFR-6 | 可回滚：每个里程碑可编译、行为等价、可回滚 |

## 6. 交付验收总则

每个 FR 的「完成」必须同时满足：
1. 对应 AC 全部通过（有测试/真机回归记录）；
2. 无 God Object 回退（类/方法行数门禁通过）；
3. 文档同步（DESIGN.md / CHANGELOG）；
4. 真机回归清单通过（涉及 su/解码/渲染/手势的改动）。

> 本 PRD 是「科学完整开发流程」的第 [1] 步产出。下一步是「架构师确认模块/接口/状态机设计」，然后拆任务，再进入开发。**在作者确认 D1–D3 决策前，FR-7（换肤）不编码；FR-1/FR-2/FR-3/FR-4/FR-5/FR-6/FR-9 为功能与稳定性修复，与审美决策解耦，可先行推进。**
