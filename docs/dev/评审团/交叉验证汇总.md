## 二点五、终端重度用户（R2）发现的核心断裂（此前所有评审遗漏）

### 🔴 最致命：录制→方案→重放闭环在代码层是断的

- `Engine.recordingCollect` 收集的 prompt→value **从未写回** `ScriptItem.recordedInputs`（`setRecordedInputs` 全工程零调用）
- `resolveAnswer()` 是死代码永远 `return null`
- `saveScripts` 序列化的是空 `recordedInputs`
- **结论：录了回答存方案，重放一个答案都不会回 —— 这是卖点级功能缺失**

这也直接解释了作者的困惑「方案库脚本更新要重新录制太麻烦」—— 实际上不是"麻烦"，是**录制保存根本没生效**。

### 其他一手源码实锤（R2）

1. `pendingCr` 赋值 4 次从未读取 → `\r` 覆盖进度条彻底坏掉
2. `feedAnsi` 只认 `m`(SGR)，清屏/光标序列全部丢弃
3. `hybridDecode` 的 `pendingTail` 语义不一致 → 独立乱码根因
4. GBK 分支排在 UTF-8 双字节分支前，`0xC2-0xDF` 误判
5. ELF 判定无视 shebang，带 shebang 非 ELF 脚本被强制 `sh` 执行
6. 无工作目录、无参数、无 PATH/TERM 环境
7. PTY 依赖 busybox script + `/dev/null`，退出码靠魔数
8. `abort()` 只 destroy 外层 su，不杀子进程树 → 假停止、后台 CPU 100%
9. `runningNow` 全局单例，执行中入队被静默忽略
10. 文件缺失 `return` 时 exitCode 保持 null → 显示绿点"成功"误导
11. `finalizePreset` 自杀连坐前台服务

### R2 的 P0 排序（对 PRD 的修正）

R2 明确指出 PRD 把精力放在"文件页手势/换肤"是**本末倒置**。重度用户核心痛点是终端 + 执行语义 + 录制闭环：

| P0 | 需求 |
|---|---|
| P0-1 | 终端内核重建（字节流解码 + 字符网格 + 完整 CSI + `\r`/`\t`） |
| P0-2 | 录制闭环修复（回写 recordedInputs + 删死代码） |
| P0-3 | 停止杀进程树 + 退出码独立通道 |
| P0-4 | ELF/shebang 语义 + 工作目录 + 参数 |
| P0-5 | 自建 PTY + raw mode + Ctrl-C/D |

## 二、QA 评审新发现的致命问题（此前无人提及）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **主线程同步 su 必现 ANR** | `FilesFragment.java:2895`（rename）、`3001`（new）、`3302`（chmod）、`2855`（detail）、`2838`（openEditor）—— 均在主线程 `OnClickListener` 里同步 `Engine.INSTANCE.exec()`，走 `su()` 3次重试+350ms sleep |
| 2 | **resolveAnswer 空实现 → 自动应答根本没实现** | `Engine.java:1344-1346` 直接 `return null`，PRD 的 AnswerRuleMatcher 是空壳 |
| 3 | **无换行提示(Password:) 导致录制/重放 key 对不上** | `promptKey` 依赖 `\n` 才 flush，`currentPartial` 无限累积，录制重放永远失配 |
| 4 | **非 PTY 路径退出码不可靠 → 失败脚本标绿 exit0** | `exitProbe` 只在 usePty 分支注入，非 PTY 直接 `su -c inner`，waitFor 拿 su 退出码 |
| 5 | **abort 只杀 busybox script 外壳，内层 sh 成孤儿继续跑** | `currentProc.destroy()` 杀的是外壳 |
| 6 | **su() 3次重试对 mv/rm 非幂等命令有副作用** | 第一次成功但 waitFor 非0，第二次重试对已删/已移文件再执行 |

## 三、PRD AC 与现状代码的断层（QA 关键结论）

QA 指出：**PRD 的 AC 是为「重构后目标态」写的，不是为「现状代码」写的**。按现状验收，AC1.2/1.3/1.4/1.6/2.x/3.x/4.x/5.x 全部 fail（例如 `item_file.xml` 是 `ellipsize=end` 与 AC2.1 的 `middle` 相反；无 AppEventBus 且文件页执行不切队列页与 AC5.1 矛盾）。

**建议**：PRD 增加「现状基线 AC」，以区分「重构前已坏」和「重构引入回归」。

## 四、架构评审的两个决定性遗漏（比拆类更优先）

- **遗漏1：没有「线程/执行器模型」** —— 拆类后若继续裸 `new Thread`，God Object 拆开但线程地狱原样迁移。
- **遗漏2：没有「消灭静态单例」硬门禁** —— `Engine.INSTANCE` 被 100+ 处直调，只要它还在，ArchUnit 分层规则形同虚设。

**R5 金句**：*「先治『全局单例 + 裸线程 + 无同步』，再谈拆 God Object；否则拆出来的只是更碎的泥巴球。」*
