## 二、架构评审技术债 Top 10（R5，最高价值）

按「不改会爆」严重度排序，均有源码行号：

1. **termBuffer 跨线程无同步 + trimTerm 切断标记对** → 数据竞争 + 渲染错位（`Engine.java:83,168-189`）
2. **runQueue check-then-act 竞态 + currentProc 非 volatile** → 双跑/关错进程（`Engine.java:546-557,894`）
3. **静态 scripts/presets ArrayList 跨线程无锁** → ConcurrentModificationException 崩溃（`Engine.java:75-76`）
4. **execBytes("cat") 整文件读入内存** → OOM（`EditorActivity.java:327`）
5. **UI 线程同步调 su** → ANR（多处）
6. **bindSwipe 手势状态机 + gestureBusy 共享** → 虚影/闪退（`FilesFragment.java:1571-1800`）
7. **SharedPreferences apply() 异步 + System.exit(0)** → 丢数据（`Store.java:40-57`）
8. **每文件一次 su 进程 N+1** → 慢 + KSU 拒绝（`FilesFragment.java`）
9. **finalizePreset System.exit(0) 硬杀** → 崩溃式退出（`Engine.java:759-760`）
10. **emit("log") 无帧合并 + TextView 全量重绘** → 主线程打爆（`Engine.java:126-183`）

### R5 架构评审的两个「决定性遗漏」（比拆类更优先）

- **遗漏1：没有「线程/执行器模型」** —— 拆类后若继续裸 `new Thread`，God Object 拆开但线程地狱原样迁移。
- **遗漏2：没有「消灭静态单例」硬门禁** —— `Engine.INSTANCE` 被 100+ 处直调，只要它还在，ArchUnit 分层规则形同虚设。

**R5 金句**：*「先治『全局单例 + 裸线程 + 无同步』，再谈拆 God Object；否则拆出来的只是更碎的泥巴球。」*
