# HazeRoot 新手易用性评审报告

> 评审角色：一名「不太懂 root、第一次用这类工具」的普通 Android 用户
> 评审对象：HazeRoot（Android root 脚本执行器）
> 评审视角：专挑「看不懂、不会用、被吓退」的地方
> 依据资料：`MainActivity.java`、`QueueFragment.java`、`Engine.java`、`Store.java`、`SplashActivity.java`、`ManualActivity.java`、`values/strings.xml`、`values-zh-rCN/strings.xml`、`layout/fragment_queue.xml`、`layout/activity_main.xml`、`README.md`、`docs/dev/HazeRoot-战略修正与生态展望.md`、`docs/dev/HazeRoot-PRD.md`

---

## 0. 一句话结论（先说重话）

**HazeRoot 现在是一款「写给会 root 的人」的专业工具，而不是一款「能让不会 root 的人上手」的产品。**

战略文档《战略修正与生态展望》里写的「降低门槛 = 引导式体验，不是阉割专业度」，在**代码层面几乎还没有落地**：未 root 时用户得到的不是文档里承诺的「永久/临时/PC 引导三选一」（FR-11），而是一句「请确认设备已刷入 Magisk / KernelSU / APatch 之一」和「打开管理器 / 重新检测 / 取消」三个按钮。

PRD 也明确写着「核心目标用户 = 进阶 root 用户 / 脚本作者 / 从 MT 管理器迁移来的效率工具用户」——**它本来就不是为新手设计的**。所以下面的问题，不是「代码 bug」，而是「产品定位与『未来想降低门槛』这个战略目标之间的巨大落差」。

## 1. 首次启动：第一屏看到什么，root 检测失败会怎样

### 1.1 真实发生的过程（基于源码）

1. 冷启动先进入 `SplashActivity`（品牌动画，可点击跳过）。
2. 进入 `MainActivity` 后，`maybeOnboardPermissions(true)` 弹出**一次性**「授权引导」对话框（用 `perm_onboard_v1` 标记记录，只弹一次）。
3. 对话框文案是 `perm_onboard_msg`：

   > 「HazeRoot 需要以下授权才能正常工作：
   > ① 通知权限 — 执行队列时在通知栏显示运行状态，并防止后台执行被系统杀掉（Android 13+）。
   > ② Root 权限 — 所有脚本 / ELF 都以 Root 身份执行，未授权则无法运行任何脚本。
   > 不授权时对应功能不可用，届时会弹窗提醒。可随时点 Root 状态行重新引导。」

4. 点「开始授权」→ 先请求通知权限（`POST_NOTIFICATIONS`）→ 再走 `onboardRootStep()` 检测 root。
5. `checkRoot()` 最多重试 3 次、每次 `waitFor(3000ms)` + 失败后 `sleep(600ms)`，**最坏情况下这个检测过程约 10 秒处于静默状态**。
6. 检测失败 → 弹出 `root_denied_msg`：

   > 「未获取 Root 权限。
   > 请点「打开管理器」，在 Root 管理器中允许 HazeRoot 获得 Root/su 授权，然后回来点「重新检测」。」

7. 如果检测不到任何 root 管理器，点「打开管理器」会 toast `root_no_mgr_found`：
   > 「未找到已安装的 Root 管理器应用。请确认设备已刷入 Magisk / KernelSU / APatch 之一。」

### 1.2 新手内心独白

> 我下载了 HazeRoot，点开，先看到一个 logo 动画，还挺好看的。
> 然后突然弹出一个框，标题叫「授权引导」，里面写着「通知权限」「Root 权限」「所有脚本 / ELF 都以 Root 身份执行」。
> 我完全懵了——什么是 Root？什么是 ELF？我连「脚本」具体指什么都不知道。
> 我点了「开始授权」，弹了个系统框让我允许「通知」。我想：我就想跑个脚本，为什么要通知权限？算了，允许吧。
> 然后它开始转……等了好几秒没反应。我以为手机卡了。
> 过一会儿又弹一个框：「未获取 Root 权限，请点『打开管理器』，在 Root 管理器中允许 HazeRoot 获得 Root/su 授权」。
> 什么管理器？我手机上根本没有叫「管理器」的东西。
> 我点了「打开管理器」，屏幕一闪，出现一行小字：「未找到已安装的 Root 管理器应用。请确认设备已刷入 Magisk / KernelSU / APatch 之一」。
> 刷入？Magisk？KernelSU？APatch？这些词我每一个都不认识。
> **于是我关掉了 App，去应用商店搜「一键 root」，或者干脆卸载了。**

### 1.3 批判点（具体）

| 问题 | 证据 | 严重度 |
|---|---|---|
| 首次弹窗一次性塞进「通知权限 + Root 权限」两个概念，且用词全是行话 | `perm_onboard_msg`（strings.xml:338-344） | 高 |
| 文案里出现 `su`、`ELF`、`Root 身份`，没有任何一处解释这三个词 | 同上 | 高 |
| root 检测最坏约 10 秒无反馈，无进度提示，像卡死 | `Engine.checkRoot()` 3 次重试×3s + 2×600ms 间隔（Engine.java:257-308） | 中 |
| 未 root 的兜底是「打开管理器」+「请确认已刷入 Magisk/KernelSU/APatch」，把门槛直接甩给用户 | `root_no_mgr_found`（strings.xml:388）、`root_denied_msg`（strings.xml:384-386） | **致命** |
| 战略文档承诺的「未 root 三选一引导（永久/临时/PC）」**根本没有实现** | 战略文档 FR-11 明确「本轮不实现」（战略文件:141-142）；代码里未 root 只有「打开管理器/重新检测/取消」 | 致命（定位落差） |

## 2. root 概念门槛：这些概念 UI 上有没有解释？

### 2.1 逐词核查结果

我在 `strings.xml`（455 条）、`values-zh-rCN/strings.xml`、`manual.html`（约 1.8MB 使用手册）、`README.md` 里逐词搜索了这些概念：

| 概念 | UI 是否解释 | 证据 |
|---|---|---|
| root（根权限） | ❌ 无 | 全文无「root 是什么」「什么是 root」 |
| su | ❌ 无 | `manual.html` 出现 396 次，但都是命令示例，无释义 |
| 提权 | ❌ 无 | 全文 0 次 |
| 脚本（shell 脚本） | ⚠️ 弱 | 只有「添加脚本」「脚本路径」这类功能词，从没解释「脚本 = 一个会在手机上执行命令的文件」 |
| ELF | ❌ 无 | 只在文件详情出现「ELF 二进制」（`detail_type_elf`），以及编辑时 toast「ELF 二进制无法用文本编辑器打开」（`err_elf_edit`），无释义 |
| Magisk / KernelSU / APatch | ❌ 无 | 只在 root 未获取时报错时出现，无「这是刷入手机来获得 root 权限的工具」的解释 |
| 绝对路径 | ❌ 无 | 「直接填写脚本绝对路径」（`add_manual_desc`）这个词本身就是行话 |

### 2.2 新手内心独白

> 首页顶部有一行小字，写着「未获取 Root」。
> Root 是什么？是「根」吗？手机为什么要有根？
> 我又往下看，看到一个「按顺序执行」按钮和一个「添加脚本」按钮。
> 脚本……是电视剧那个「剧本」吗？我是不是要自己写代码？可我根本不会写代码。
> 我壮着胆子点了「添加脚本」，弹出来三个选项：浏览文件、从链接导入、手动输入。
> 我点「手动输入」，跳出一个输入框，里面已经预填了一串奇怪的东西：`/data/adb/HazeRoot/xxx.sh`。
> 这是什么？一堆斜杠和字母，`adb` 是啥？我是不是要会编程才能用这个 App？
> **我怂了，退出了。**

### 2.3 批判点（具体）

- **概念零解释**：root / su / 提权 / 脚本 / ELF / Magisk 这六个「新手第一道墙」，在 UI 和手册里**一个都没有被解释**。`manual.html` 是「操作手册」（有 guide_1~7 的操作步骤），不是「概念科普」——它假设你已经知道 root 是什么。
- **术语中英混杂**：root 状态行的成功态字符串是英文 `Root Active`（`root_active`），失败态是中文「未获取 Root」（`root_denied`）。同一行状态，一会儿英文一会儿中文，进一步加重「这不是给我用的」的感觉。
- **默认路径劝退**：手动添加脚本默认预填 `/data/adb/HazeRoot/xxx.sh`（`addScriptDialog` 里 `field$default(this, "/data/adb/HazeRoot/xxx.sh", ...)`），这是纯 root 技术圈的行话，对新手是「直接劝退级」信息。

## 3. 添加脚本到执行：要理解多少概念、点多少步

### 3.1 完整路径拆解

从一个新手「我想跑一个脚本」到「跑起来」，实际要经历的完整链路：

```
点「添加脚本」
  └─ 底部弹层三选一：
       ├─ 浏览文件 → 切到「文件」页进入 pick 模式 → 靠理解「点选脚本即入队」
       ├─ 从链接导入 → 填 http(s) 链接 + 保存名
       └─ 手动输入 → 填「脚本绝对路径」+ 显示名称
  └─ 脚本入队
点「按顺序执行」
  └─ 静默检测 root（最长约 10 秒）
  └─ 若 root OK → 检查通知权限 → 未授权再弹窗
  └─ 开始执行
```

### 3.2 概念与步骤计数

| 维度 | 数量 | 明细 |
|---|---|---|
| 必须理解的隐性概念 | **6 个以上** | root、通知权限（为什么执行要它）、队列、脚本/ELF 区别、绝对路径、退出码 |
| 从「想跑」到「跑起来」的最少点击 | **约 5~7 步** | 添加脚本→选入口→（选文件/填路径/填链接）→确认→点执行→（过 root 门）→（过通知门） |
| 中间可能出现的系统弹窗 | **最多 3 个** | 授权引导（首次）、root 未获取弹窗、通知权限弹窗 |

### 3.3 新手内心独白

> 我折腾了半天，终于把一个脚本加进去了（其实我还是不确定我加对没有）。
> 然后我点那个大大的「按顺序执行」按钮。
> 没反应。真的没反应。就一行小字「正在检测 Root…」。
> 我数了数，等了快十秒，什么也没发生。是不是 App 坏了？我连点了好几下。
> 然后突然跳出一个框：通知权限没开，要我「去授权」。
> 为什么执行个脚本还要通知权限啊？而且我不是刚开过吗？
> 我点了去授权，回来又点了一次执行。
> 这次终端里终于开始滚字了。但滚出来的字我一句都看不懂。

### 3.4 批判点（具体）

- **门太多**：执行前要过「root 门」和「通知门」两道闸（`withGates()`），每一步对新手都是一次「我是不是哪里没弄对」的自我怀疑。
- **静默太长**：root 检测失败时 3 次重试静默约 10 秒，期间只有一行「正在检测 Root…」，没有「最多可能等 10 秒」的预期管理。
- **通知权限的理由没讲清**：`perm_need_noti_msg` 说的是「防止后台执行被系统杀掉」——这个理由对新手抽象，他们只想知道「我就想跑个脚本，凭什么要通知权限」。

## 4. 空状态 / 引导：空队列、空文件、未 root 时有没有清晰下一步

### 4.1 各状态的现状

| 状态 | 现状 | 证据 |
|---|---|---|
| 空队列（首次） | 有 `emptyState`：图标 +「暂无脚本」+「添加一个脚本路径，开始构建执行队列」+「添加脚本」按钮；终端还有欢迎语「队列 0 个脚本 · 就绪」「› 点『按顺序执行』开始」 | `fragment_queue.xml:27-31`、`printWelcome()`（QueueFragment.java:991-1012） |
| 空方案库 | 「还没有方案。先把队列执行一遍，输入的回答会被录制，然后点上方『保存当前队列』存成方案」 | `presets_empty_note`（strings.xml:364-365） |
| 未 root | 只有顶部一行 12sp 小字「未获取 Root」（红点+红字），**没有任何「点这里看怎么办」的文字提示**；虽然 `rootBadge` 可点击，但无视觉暗示可点 | `fragment_queue.xml:11-14`、`threadRootCheck` 结果（QueueFragment.java:1378-1399） |

### 4.2 新手内心独白

> 我第一次打开，队列是空的。界面中间有个小图标和一句话：「添加一个脚本路径，开始构建执行队列」。
> 说实话这句话我也没太懂——「脚本路径」是啥？
> 但至少有个「添加脚本」按钮，我姑且点一下。
> 顶部那行「未获取 Root」的小红字，我盯着看了半天：它在提示我什么吗？我该点它吗？它看起来不像能点的样子。
> 我试着点了它一下，居然弹出一个「Root 状态」的框，里面说「未获取 Root 权限，请点『打开管理器』……」。
> **原来这行字能点！可它长得完全不像按钮，我差点就错过了。**

### 4.3 批判点（具体）

- **空队列文案仍在用行话**：「脚本路径」「执行队列」这两个词对新手不友好，应该改成「把你手机里的脚本文件加进来，按顺序一个个跑」这种大白话。
- **未 root 状态缺少强引导**：战略文档里「降低门槛」的核心场景就是「未 root 用户」，但当前 UI 对未 root 用户只有一行 12sp 红字，没有醒目的「我不知道什么是 root，点这里」入口。这是**当前产品与战略目标最大的 UI 断层**。
- **root 状态行可点击但不可发现**：`rootBadge` 有 `clickable`，但没有任何视觉提示（无箭头、无下划线、无「查看」字样），新手大概率发现不了。

## 5. 错误提示：对新手友好吗？

### 5.1 逐条审查

| 场景 | 当前文案 | 新手友好度 | 批判 |
|---|---|---|---|
| root 未获取 | 「请点『打开管理器』，在 Root 管理器中允许 HazeRoot 获得 Root/su 授权」 | ❌ 低 | 「Root 管理器」「su 授权」全是行话；对没刷过 root 的人是死胡同 |
| 找不到管理器 | 「请确认设备已刷入 Magisk / KernelSU / APatch 之一」 | ❌ 低 | 「刷入」这个词 + 三个陌生名词，无任何补救路径 |
| 脚本文件不存在 | 「!! 文件不存在: %s，已跳过（请核对文件名/路径后编辑本条）」 | ⚠️ 中 | 至少说了「编辑本条」，但没说在哪编辑、怎么编辑 |
| 退出码非 0 | 「!! 注意：该脚本异常退出，请检查上方报错」 | ❌ 低 | 「退出码」「上方报错」对新手无意义；没有「常见失败原因」的解释 |
| 通知权限被拒 | 「请到 系统设置 → 应用 → HazeRoot → 通知 手动开启」 | ✅ 较高 | 路径清楚，这条是少数对新手友好的 |
| 读取失败 | 「读取失败，请重试（Root 命令未返回结果）」 | ❌ 低 | 「Root 命令未返回结果」不解释原因、不给下一步 |
| 导入失败 | 直接拼 `e.getMessage()` 或 `"HTTP 404"` | ❌ 低 | 可能直接蹦出英文技术错误，如 `HTTP 404`、`Connection timed out` |

### 5.2 新手内心独白

> 我好不容易让脚本跑起来了，结果终端里冒出一行红字：
> `[xxx 退出码: 127]`，下面还有一行「!! 注意：该脚本异常退出，请检查上方报错」。
> 退出码 127 是什么？0 才对吗？那 127 是错在哪？「上方报错」——上面有一大堆字，哪一行才是报错？
> 我又往上翻了翻，全是 `sh: xxx: not found` 之类的东西。
> **我彻底不知道该怎么办了，只能截图发群里问别人。**

### 5.3 批判点（具体）

- **错误提示是「给会的人看的」，不是「给不会的人看的」**：能说出「退出码 127」「ELF」「su 授权」的人根本不需要这些提示；需要这些提示的人又看不懂。
- **失败后无「下一步」**：几乎所有的错误提示都停留在「告诉你出错了」，没有「出错了你可以：①…②…」的补救引导。
- **错误信息可能泄露英文技术细节**：`import_fail_fmt` 直接拼接异常 message（`MainActivity.java:727-729`），可能显示 `HTTP 404` 等英文，进一步劝退中文新手。

## 6. 新手最容易卡住 / 放弃的 5 个瞬间 + 降门槛建议

### 瞬间 ①：打开 App 被「授权引导 + root 行话」糊脸

**发生了什么**：首次启动弹「授权引导」，一次性塞进通知权限、Root 权限、ELF、su、Magisk 等概念；没刷过 root 的用户点到最后得到「请确认设备已刷入 Magisk / KernelSU / APatch」，彻底死胡同。

**降门槛建议**：
1. 首次启动改成**分步骤引导**：第一步先解释「HazeRoot 是干嘛的」（一句大白话 + 一张图），第二步再请求通知权限，第三步再检测 root。
2. 检测到「未 root」时，按战略文档 FR-11 的意图，给**三选一引导**：`① 我还没 root，带我去了解` / `② 我已经 root 了，重新检测` / `③ 我是临时/PC 用户（预留）`，而不是冷冰冰的「打开管理器」。
3. 「Magisk / KernelSU / APatch」第一次出现时，**加一句括号解释**：「（这是让手机获得 root 权限的常见工具）」。

### 瞬间 ②：手动添加脚本要填 `/data/adb/HazeRoot/xxx.sh`

**发生了什么**：「手动输入」入口预填了一个绝对路径 `/data/adb/HazeRoot/xxx.sh`，新手不知道 `/data/adb` 是什么，也不知道「绝对路径」是什么。

**降门槛建议**：
1. 默认**不预填行话路径**，改成空输入框 + 占位符「例如 /sdcard/xxx.sh（手机存储里的脚本文件路径）」。
2. 三个入口（浏览文件/链接/手动）上各加一句**一句话解释**，明确「手动输入」是给谁用的（老手），并**把「浏览文件」设为最推荐的默认入口**、排第一且高亮。
3. 增加「不确定？点这里看示例」的折叠示例。

### 瞬间 ③：点「按顺序执行」后静默约 10 秒，以为死机

**发生了什么**：`checkRoot()` 3 次重试 + 间隔，最坏约 10 秒无输出，期间只有一行「正在检测 Root…」。

**降门槛建议**：
1. 检测中显示**动态进度/文案**：「正在检测 Root…（首次可能需要几秒，请稍等）」。
2. 给 `checkRoot` 加一个「检测中」可取消状态，或至少把总等待时间控制在可感知范围并明示。
3. 执行按钮在检测期间置灰 + 显示「检测中…」，避免用户连点（当前 `withGates` 只是 `if (runningNow) return;`，检测期间按钮可能仍可点）。

### 瞬间 ④：脚本报错只看到「退出码 n / 请检查上方报错」，不知道下一步

**发生了什么**：脚本失败时终端只有 `[xxx 退出码: n]` + 「!! 注意：该脚本异常退出，请检查上方报错」，对新手无意义、无补救。

**降门槛建议**：
1. 失败时**弹出/追加一条可点卡片**：「脚本执行失败了。常见原因：① 脚本文件不存在或路径写错 ② 脚本本身有错误 ③ 缺少权限。点这里查看如何排查」。
2. 对常见退出码做**中文解释表**（如 127 = 命令找不到、126 = 无执行权限、1 = 脚本自身报错），并给出对应建议。
3. 把「退出码」这个概念在首次出现时做个悬浮解释。

### 瞬间 ⑤：未 root 只有一行小红字「未获取 Root」，找不到下一步入口

**发生了什么**：未 root 时 UI 只有一行 12sp 红字，虽然可点击但无视觉提示，新手发现不了「点它可以看怎么办」。

**降门槛建议**：
1. 未 root 时，把这一行升级为**醒目的引导条**：「未获取 Root —— 还不知道 Root 是什么？点这里了解」，带箭头或按钮样式。
2. 点击后进入一个**面向新手的「什么是 Root」科普页**（可复用 `ManualActivity` 的 WebView，但补上概念科普章节）。
3. 顶部状态行成功态也统一成中文（把 `Root Active` 改为「已获取 Root」），避免中英混杂。

## 7. 附：战略目标 vs 现状的落差清单（给作者看）

| 战略文档承诺 | 当前代码现状 | 落差 |
|---|---|---|
| 「降低门槛 = 引导式体验」（原则 C） | 未 root 只有「打开管理器/重新检测/取消」 | 未实现 |
| FR-11 未 root 三选一引导（永久/临时/PC） | 无此 UI，只有 root 报错弹窗 | 未实现（文档也标注本轮不做） |
| 「检测到未 root 时不再是冷冰冰的『无 root』」 | 顶部文字是「未获取 Root」（冷冰冰程度没变） | 部分实现（多了弹窗，但仍是行话） |
| 「PC 工具作为第一次 root 的引导」 | 完全无 | 未实现 |
| 「root 用户的操作系统，其它是能力插件」 | 当前只有单点 App | 架构预留，无用户可见 |

**核心判断**：如果作者真的想「降低门槛」，那么**当前最该做的不是再打磨终端渲染或手势（那些是给老手用的），而是先补上「新手第一次打开 App 的 30 秒」**——让一个不懂 root 的人，打开 App 后能看明白「这是什么、我要不要 root、我下一步点哪里」。

## 8. 结论

HazeRoot 在**专业能力上完成度很高**（终端渲染、ANSI/GBK 解码、队列、方案重放、双窗文件管理都做得很细），但它目前是一个「**高门槛的专业工具**」，与「未来想触达普通用户」的战略愿景之间存在**尚未弥合的鸿沟**。

对「什么都不懂的新手」而言，这个 App 现在会让他们在 **打开 30 秒内就放弃**——不是因为功能不好，而是因为**满屏的 root / su / ELF / Magisk 术语、预填的 `/data/adb/...` 路径、静默 10 秒的检测、以及「退出码 n」式的错误提示**，构成了一道道「这不是给我用的」的心理墙。

**降门槛不是砍功能，而是把「行话翻译成人话」、把「报错翻译成下一步」、把「检测翻译成引导」。** 这三件事，目前一件都还没做。
